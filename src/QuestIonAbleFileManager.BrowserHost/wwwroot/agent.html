Agent guide

No headset app is required for these ordinary ADB operations. Developer mode, headset debugging authorization and an accessible transport are still prerequisites.

QFM host

The optional Windows BrowserHost serves this interface and a closed same-origin API. Start it explicitly with the configured ADB executable and private session token. Connect using that token, refresh devices, select an exact ready target and read its status. The token remains in tab memory and is cleared on disconnect; it is never part of a URL or browser storage.

WiFi setup and device settings require the matching approval checkbox. Coordinate the actual device slot and supervisor custody first. A confirmed receipt requires operation-specific effective readback; HTTP success alone is not confirmation. Do not automatically repeat a pending or unknown mutation. Use “Read original result” with the retained request ID. A host restart invalidates its session; retain uncertainty and inspect current state before selecting any recovery through the documented owner route.

The browser host invokes the same immutable OperatorCommand and Core executor used by QFM CLI. The first API supports devices/status, classic WiFi enable/connect and awake/normal settings only. The chosen duration bounds the proximity hold; stay-awake remains enabled until an explicit Restore normal change. It does not expose raw shell, a generic command runner, Fleet authority or a new watchdog.

USB proof

Use a WebUSB-capable desktop browser in a secure context, including localhost. Windows needs a compatible USB driver/interface association. “Choose USB headset” opens the browser chooser; headset RSA authorization can require physical access. These prompts may be outside a browser agent's DOM and need a human. A browser backend without USB access must report unavailable rather than bypass permissions.

This mode uses pinned Tango packages bundled locally to read fixed serial/boot/battery facts, with explicit handle selection. It never changes power, transport or installed packages. An interface already held by shared ADB can be busy. Keep the shared daemon and existing watchdog running; use host mode instead of killing it.

Authentication keys are retained in this browser origin's IndexedDB by Tango. Disconnect releases the connection but retains the key. Clearing this origin's site data removes the local key; revoking debugging authorizations on the headset is a separate protected action. A folder on a shared origin is not an isolated permission boundary.

Typed alternatives

When browser permission or UI automation is unavailable, use the selected qualified QFM CLI with its configured ADB. These are the same owner implementation's ordinary routes:

questionable-file-manager.exe devices --json
questionable-file-manager.exe device status --serial <exact-target> --json
questionable-file-manager.exe wifi connect --host <known-host> --port 5555 --confirm-wifi-adb --json
questionable-file-manager.exe device keep-awake --serial <exact-target> --on --duration-ms 3600000 --confirm-device-settings --json

Read nested mutation/result fields and preserve pending outcomes. Shell exit zero is insufficient. Ordinary keep-awake does not enroll a device or adopt Fleet scheduling. Changes through CLI require the same real target authority and current custody as browser actions.
