# Verified browser download dependency

The self-hosted SHA-256 module is built from `@noble/hashes` **2.4.0**, MIT,
and esbuild **0.28.2**. `package-lock.json` pins package integrity and the entire
build dependency graph. Only upstream SHA-256 is bundled; QFM does not implement
a cryptographic primitive. There are no runtime CDN imports, workers or private
caches.

Upstream provides incremental `sha256.create().update(bytes).digest()`:
[API and security notes](https://github.com/paulmillr/noble-hashes/tree/2.4.0).
The signed release identifies source commit
`663c2aeeffc308ac0cded59bd32f7c212adacfc2`:
[release](https://github.com/paulmillr/noble-hashes/releases/tag/2.4.0).
The npm package metadata reports the same `gitHead`, MIT license and version.

With Node.js and npm on PATH, run in this directory:

```powershell
npm ci --ignore-scripts --no-audit --no-fund
node build.mjs
node build.mjs --check
```

The checked-in outputs are `wwwroot/vendor/noble-sha256.js`,
`NOBLE_HASHES_NOTICES.txt` and `noble-hashes-packages.json`. The check compares
all generated bytes, including the package SHA-512 integrity, source commit,
license SHA-256 and bundle SHA-256 in the inventory. Preserve the MIT notice
when distributing the bundle. esbuild is a build dependency only.

## Save helper

Import `saveArtifact` from `wwwroot/verified-download.js` and call it directly
from the Save click, with no preceding asynchronous work:

```javascript
const result = await saveArtifact(receipt, {
  headers: sessionHeaders,
  signal: cancellation.signal,
  onProgress: ({phase, bytesReceived, totalBytes}) => updateProgress(phase, bytesReceived, totalBytes)
});
```

`receipt` contains only `id`, `fileName`, `sizeBytes`, `sha256`. The helper
snapshots and validates these fields before opening the picker. `url` may be
omitted; if supplied, it must resolve to exactly the same numeric-loopback
origin's `/browser/v1/artifacts/{id}` route, with no query, fragment or userinfo.
Requests use GET, no-store, omitted ambient credentials and rejected redirects.
Caller headers stay in memory; receipt hash/size headers are bound explicitly.

The picker is invoked before the first await or network request. Where supported,
received chunks go through pinned incremental SHA-256 and the chosen writable.
Size and digest must match before close. Maximum artifact size is 1 GiB. Without
the picker, `maxBufferedBytes` defaults to 256 MiB and can only be lowered. Larger
artifacts fail before any request with a supported Chrome/Edge or CLI alternative.
The buffered path bounds response reads before creating a Blob and using SubtleCrypto.

Return values contain `{state, mode, artifact}`. Streaming returns `saved` only
after verified close; buffered mode returns `downloadStarted`, which acknowledges
browser handoff and does not claim completion of the browser's disk-save flow.
Progress phases are `choosingDestination`, `receiving`, `verifying`, `saving`,
`complete`, `downloadStarted`. Progress exceptions do not control file commit.

The receive/write/verify/close lifetime starts after picker selection and defaults
to 300 seconds. `timeoutMilliseconds` may be lowered to 1..300000 milliseconds;
human chooser time is excluded. `cleanupTimeoutMilliseconds` is 1..2000 and
defaults to two seconds. The deadline interrupts waiting on native promises too,
including a stalled create, write or close. A create that resolves after timeout
has an abort-only continuation; it never receives a later write/close. Pending
native work or failed/timed-out cleanup remains explicitly `cleanupPending`.

Errors are sanitized `ArtifactDownloadError` instances with stable `code`, and
optional `status`, `alternative`, `cleanupPending`, `saveOutcomeUnknown`. The
last flag means close was attempted but successful completion was not acknowledged;
inspect the selected destination before retrying. Failed writer aborts set
`cleanupPending`; no successful-save event is emitted. Cancellation during HTTP
read/write aborts the owned writable. Cancellation cannot undo an acknowledged
close or a buffered download already handed to the browser. Tie the supplied
signal to the current page's explicit Cancel/disconnect lifecycle.

The additional exports are `ArtifactDownloadError`,
`MAXIMUM_BUFFERED_DOWNLOAD_BYTES` and `MAXIMUM_ARTIFACT_BYTES`. There is no
private cache, worker, storage, key, device or arbitrary command surface.

Behavior tests exercise the shipped ES module using Chromium with mocked
picker/fetch streams and no server or device:

```powershell
node --test tools/browser-ui/download.test.cjs
```

Run that command from the repository root using the existing Playwright runtime
and `NODE_PATH` setup described in `tools/browser-ui/README.md`.
